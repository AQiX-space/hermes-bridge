# Hermes Connector 0.3 beta.2 — штатное автоматическое обновление

ТЗ владельца: **не выдавать путь к EXE и не требовать ручную загрузку/установку**. Коннектор сам находит обновление, загружает, проверяет, устанавливает и восстанавливает туннель. Значок в трее и постоянный режим не отключают механизм.

## Реализовано

- Проверка GitHub Releases при старте и каждые 6 часов; исключаются draft и версии без канонической HTTPS-ссылки на `AQiX-space/hermes-bridge`, а также без SHA256 asset digest. При ошибке проверки старая версия и SSH-туннель продолжают работу.
- Автоматический путь теперь **не показывает «Нажми обновить»**. Обновление проверяется и загружается в фоне, в том числе когда существует работающий обратный SSH-туннель. Действия с незавершённой регистрацией/отзывом отложены.
- После завершения скачивания и SHA256-проверки встроенный `HermesBridgeUpdater.exe` запускается с заранее проверенным хешем, а старый экземпляр **закрывает только локальный процесс/туннель, без server revoke**. Helper ждёт выхода старого процесса, делает замену с копией `.previous`, запускает новую программу с `--resume-update` и откатывает прежние байты, если новый процесс сразу падает.
- Если новый EXE не запускается, helper возвращает предыдущую версию, пробует запустить её, и сохраняет SHA256 неудачного выпуска в 24-часовой карантин (не повторяет аварийное обновление бесконечно). При откате на старый клиент без `--resume-update` откроется его обычный интерфейс; восстановление удалённого доступа тогда требует отдельной проверки.
- Ранее подключённый support и resident пытаются восстановить прежнее одобрение и активный порт по сохранённому DPAPI-билету. Для resident после успешного старта обновляется привязка HKCU Run к новому исполняемому файлу.
- Для read-only исходного EXE обновление устанавливается в выделенный управляемый EXE в профиле пользователя; **старый установленный файл не перезаписывается в момент подготовки**. Новый экземпляр обновляет автозапуск и ярлык.
- Первоначальная загрузка (0.2.9/0.3.0-beta.0) **не умеет настоящую автоматическую установку**: уже выпущенный старый код нельзя изменить удалённо. Требуется единовременный доверенный переход на эту версию или другое явно разрешённое средство развёртывания. После обновления встроенный механизм работает автономно.

## Безопасность/ограничения

- Текущий GitHub Releases-источник полагается на GitHub HTTPS и официальный `asset.digest` (SHA-256) **из того же аккаунта публикации**. Это контроль целостности, но **не независимая подпись издателя**. Сторонний захват GitHub publishing credentials может скомпрометировать обновления. Перед массовым общедоступным авторазвёртыванием необходим Authenticode или отдельная независимо подписанная update-manifest. Ранее настроенный RSA-манифест сейчас недоступен (`sub.aqix.ru:3443` соединение отвергает), поэтому не считать этот канал принятым.
- Бета 0.3.0-beta.2 из ветки не является публичным обновлением, пока релиз не опубликован и не проверен на интерактивном компьютере владельца. Старый работающий МОСТ не прерывать ради проверки кода.
- Не выполняет привилегированную установку через чужую Windows-учётную запись; UAC вызывается отдельно, только по воле пользователя.
