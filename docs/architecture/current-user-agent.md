# Hermes Connector — пользовательский исполнитель команд (0.3.0)

**Норматив владельца, 2026-11-19:** коннектор наследует **права Windows пользователя, который его запустил**. Доступ через системный `sshd` под `aqixssh` либо другой учётной записью **не входит в основной режим**. Вход под другим пользователем может быть отдельной функцией в будущем.

## Выполнение

- Hermes Connector работает в интерактивном сеансе Windows текущего пользователя (напр. `ALEXHUB\\Alex`). Выполнение команд — дочерним `powershell.exe` с `UseShellExecute=false` и **без** UserName/Password, RunAs, UAC, System/службы или чужих токенов. Уровень прав совпадает с текущим токеном коннектора, включая статус elevation.
- Существующий Windows OpenSSH **Client** остаётся только транспортом: outbound `ssh -R 127.0.0.1:<server-slot>:127.0.0.1:<ephemeral-agent-port>` через GR1/GR2. Системный OpenSSH **Server** и TCP/22 не требуются, не устанавливаются и не перенастраиваются.
- Агент слушает **только 127.0.0.1** (случайный свободный локальный порт). При Stop/revoke/выходе listener останавливается, а текущий дочерний процесс завершается.
- Session agent стартует только после подтверждённого broker approval и чтения DPAPI-защищённого high-entropy билета владельца; срок доступа определяется одобрением, session lifetime и revocation.

## Авторизация команды

Одобрение самого МОСТ (код) не равно публичному shell-доступу. Административная операторская команда подписывается **HMAC-SHA256** с ключом `SHA256("Hermes user-agent HMAC v1\\n"+ brokerTicket)`. Ticket известен только клиенту в DPAPI и уполномоченному оператору broker с доступом к SQLite. На проводе передаются `ts`, `nonce`, `script` и `mac`; сам ticket **не передаётся и не журналируется**. Пределы: timestamp 60 секунд, UUID nonce 32 hex (повторы отклоняются), до 4096 символов команды, 30 секунд исполнения, вывод до 32К символов на поток, одно одновременное исполнение. При отключении все новые команды запрещаются.

Операторский скрипт `ops/hermes-user-command.py` делает проверенный SELECT одного активного `approved` допуска на заданном слоте, проверяет `expires_at` и подписывает запрос локально на том же доверенном техническом узле. Его нельзя запускать в открытом терминале третьей стороны или давать неавторизованному пользователю доступ к SQLite.

## Приёмка и риски

1. На разных Windows пользователях запустить коннектор и проверить идентичность `WindowsIdentity.GetCurrent().Name` и результат авторизованного `whoami`/`[WindowsIdentity]::GetCurrent().Name` — **они должны совпасть**.
2. Проверить отказ неверной подписи, истёкшего запроса, повторного nonce, превышения лимита команд, отказ при Stop.
3. Через GR2 с одобренным билетом выполнить `whoami` операторским инструментом, сверить с реальным пользователем, под которым пользователь запустил GUI; после Stop убедиться, что порт исчез, а процесс завершён.
4. Провести revoke на Gate с контролем порта. Нельзя объявлять полную приёмку, пока нет сквозного теста на целевом Windows и работающего закрытия сессии на LV1.

**Риск:** компрометация оператора/SQLite broker даёт исполнение в рамках явно одобренного времени, с правами запустившего коннектор пользователя. Следовательно, backend, Зион и доступ к операторскому узлу остаются критической границей доверия. Не использовать повышенные права коннектора без необходимости. В этой версии нет desktop screen-sharing/UI-клика: реализовано выполнение команд в текущем пользовательском токене.

Версия 0.2.9 использует старую SSH-схему и не соответствует этому требованию. Нельзя считать её исправленной без обновления клиента.
