# Hermes Connector 0.3.0-beta.1 — UAC и права пользователя

**Объём:** UAC запускается только по явной команде пользователя; обычная диагностика и постоянный агент не требуют прав администратора по умолчанию. Создавать второго скрытого SSH-пользователя запрещено. Пример: запущено под `ALEXHUB\\Alex` — подписанные команды `UserSessionAgent` исполняются от имени `Alex`, c токеном коннектора.

## Интерфейс

- В окне отображается `Исполнение: <учётная запись> [обычные права]` или `[администратор]`.
- В режиме поддержки — пункт `Перезапустить от администратора`, в любом режиме — тот же пункт в трее.
- При включении постоянного режима показывается **трёхвариантный запрос**: увеличить права только текущей сессии, остаться с обычными правами либо отменить смену режима.
- UAC/отмена: `ShellExecute` с глаголом `runas`, **никаких введённых в коннектор паролей**, настройки UAC не обходятся. Отмена UAC сохраняет старый процесс и туннель.
- Проверяется ограниченный UAC-токен именно данного администратора (`TokenElevationType.Limited`). Если Windows требует пароль *другой* учётной записи, переход блокируется: нельзя перенести DPAPI ticket и текущий SID к чужому администратору.

## Передача активного сеанса

- После успешного запуска `runas` старый процесс **сразу закрывает локальный SSH и socket-исполнитель**, но **НЕ отзывает** одобренное сервером разрешение; билет сохраняется в пользовательском DPAPI-хранилище.
- Новый процесс запускается с `--elevated-from-sid <current SID> --resume`; проверяет тот же SID и администраторский токен; ждёт освобождения глобального однопользовательского мьютекса не более 15 секунд и пробует восстановить **то же разрешение МОСТ**, без генерации нового кода.
- При недоступном шлюзе новую сессию не выдавать за подключённую. В случае падения новой программы старый билет остаётся на диске для повторного запуска после устранения ошибки.
- На GR2 уже есть проверенный серверный механизм socket-scoped revoke; при UAC-переходе его *не вызываем* — это не действие «отключить доступ».

## Непрерывная служба

- Обычный автозапуск `HKCU Run` после входа в Windows **не создаёт повышенный UAC-токен**. Так и должно быть: постоянно работающий администраторский агент расширяет поверхность атаки. Для действительно системной работы до логина нужна **отдельная архитектура** и явный выбор владельца.
- Постоянный режим может работать с минимальными пользовательскими правами; для системных операций рекомендуются краткоживущие повышенные действия.

## Приёмка

1. CI Windows: тесты токена, same-SID, CLI-флагов, глобального mutex/handoff и сравнения версий.
2. На ALEXHUB войти именно как `Alex`, открыть новую beta, проверить статус обычных прав; запросить повышение, подтвердить UAC и убедиться в `Alex` + `ElevatedAdministrator=true` через подписанную команду МОСТ.
3. Проверить отмену UAC: старый туннель продолжает работать; проверить восстановление через тот же слот после согласия, с `doctor.ok=true` и прежним билетом.
4. Выключить коннектор, отозвать доступ штатным способом; проверить, что нет активного TCP-порта и служба Gate не закрыла другие сессии.
5. Проверить, что после Windows login автозапуск не объявляет себя администратором и не повышает права без согласия; проверить GUI/трей, UAC, логи и отсутствие секрета в журнале.

**До этой живой проверки beta остаётся тестовой.** Не публиковать её в открытый GitHub Release, потому что старые клиенты умеют обнаруживать prerelease и могут обновиться без завершённой приёмки.
