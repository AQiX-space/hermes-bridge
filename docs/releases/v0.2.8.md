# Hermes Connector 0.2.8 — аварийный доступ GR1/GR2 (предварительный выпуск)

**Статус: prerelease / предварительный выпуск, не полная эксплуатационная приёмка.**

- Новая регистрация: проверка GR1 `gr1.touch01.top`, при недоступности — GR2 `gr2.touch01.top`. Ручной выбор шлюза через меню в трее.
- Отдельные билеты разрешений и исходные серверные адреса: уже созданная заявка не переезжает на другой Gate. После перезапуска ожидающая заявка восстанавливается на исходном сервере.
- Жёсткая привязка новых заявок к DE2 убрана, при условии доступности GR2 и разрешения оператора.
- В приложении отображается версия 0.2.8.
- Сервер GR2 (LV1): HTTPS/TLS и reverse SSH проверены из административного шлюза; тестовый туннель до локального HTTP прошёл.

## Ограничения и приёмка

- **Нет Authenticode-подписи издателя.** Defender проверяется в Windows CI. Исполняемый файл получает SHA256-digest через GitHub Releases API и проверяется клиентом при скачивании. Подписанного независимого release manifest в этом канале нет.
- **Не исправлен серверный принудительный отзыв работающей SSH-сессии на GR2.** Клиент останавливает локальный SSH-процесс перед отзывом, но отдельный серверный revoke на живом туннеле пока не прошёл тест. Новое привилегированное исправление подготовлено, но не установлено.
- Автоматический выбор действует для **новых регистраций**. Активное разрешение не переносится между GR1 и GR2 без повторного безопасного одобрения. Если GR1 недоступен и там осталась активная заявка, нужен контролируемый аварийный отзыв.
- Реальный GUI/операторский Windows end-to-end тест на целевой машине ещё не выполнен. Не заявлять полностью завершённую задачу без него.
- При обновлении завершите действующую сессию и добейтесь подтверждённого отзыва перед установкой.

Rollback: сохранённая предыдущая версия `.previous`; штатный updater проверяет хеш и восстанавливает предыдущий EXE при ошибке запуска. Версия 0.2.7 остаётся в Releases для ручного отката при необходимости.
