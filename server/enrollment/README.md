# Hermes Connector enrollment broker — experimental

An unprivileged localhost-only Python service accepts PUBLIC ED25519 device keys (`POST /v1/enroll`), returns random tickets, and provides polling (`GET /v1/enroll/{ticket}`). Devices remain pending until a trusted local operator explicitly approves. The operator CLI runs in dry-run mode by default; `--apply` is a privileged production write, only after explicit approval for that particular enrollment. It backs up `authorized_keys`, installs per-key `permitlisten` restrictions, and restores the backup if the database update fails. A basic 3-requests/15-minutes per-device rate limit now exists; reverse-proxy per-IP limits, authenticated HTTPS, revocation of live sessions, and production deployment are not yet implemented. Do not expose HTTP listener publicly or treat device registration as permission without operator approval.

Production endpoint on DE2: `https://de2.nod.aqixnet.com:18512/v1/enroll`. Dedicated Nginx 18512 with Lets Encrypt, reverse proxy to localhost 18511; per-IP rate limit; UFW 18512. SSH daemon on 22471 permits localhost reverse listens for approved keys; `authorized_keys` per-device `permitlisten` restriction remains mandatory. Initial approval still requires a trusted operator, not autonomous issuance. GitHub updates remain independent of this endpoint.

## Temporary device operations (operator only)

`service.py --db /var/lib/hermes-enrollment/requests.sqlite3 pending` lists unexpired requests. Approval supports `approve --ticket TICKET --host de2.nod.aqixnet.com --hostkey 'ssh-ed25519 ...' --slot auto` (dry run); adding `--apply` makes an atomic, backed-up change to `authorized_keys`. The server allocates a free slot in 23000–24999. Verify device identity before approving.

`revoke --ticket TICKET` previews removal of a previously approved device; `revoke --ticket TICKET --apply` removes only that device's SSH authorized key, keeps a timestamped backup and marks its registration revoked. **Warning:** this blocks future SSH authentications but does NOT immediately terminate an existing SSH session or revoke a live remote forward. For urgent revocation, also terminate that device's existing SSH session through a separately reviewed operator operation. Do not mistake this command for a full live-session kill switch. Temporary Windows PCs are never a gateway dependency.

Production broker deployment is a separate, owner-approved change: do not assume that a GitHub main branch push updates `/opt/hermes-enrollment/service.py` on DE2.

## Протокол МОСТ: пятизначный код

При первом нажатии «Подключить Гермеса» клиент получает случайный пятисимвольный код и показывает его владельцу. После команды «Протокол МОСТ» оператор показывает владельцу найденный код и устройство; **без утвердительного ответа владельца разрешение не выдаётся**. Одобрение выполняется только с `approve --ticket ... --code XXXXX --host ... --hostkey ... --slot auto --apply`. Код привязан к конкретному ключу и билету на 15 минут. Ошибочный код не открывает доступ. `pending` возвращает список с кодами только локальному администратору DE2; не выставлять этот CLI в публичный HTTP. Оператор обязан проверить название и отпечаток ключа.

Для обновления действующей службы на DE2 нужны отдельные backup, миграция SQLite (в `__init__`) и smoke-test до допуска версии beta.12 для владельца. Существующая beta.11 не умеет показывать код, поэтому не объявлять новую схему завершённой до совместного развёртывания.

## Stale-key recovery (2026-10-24, development release)

The broker now defaults **new** approvals to a bounded **7200-second lease**. The existing Gate reaper revokes expired leases, removes their scoped authorization and verifies that the old reverse listener is closed before freeing its key/slot. This does **not** retroactively expire legacy grants with `expires_at=NULL`; do not silently migrate or revoke them.

Fast operator-only diagnostic: `service.py --db ... preflight --code Sa45`. It returns the matching device and conflict metadata (old code, slot, listener state, expiry), **never** bearer tickets or device public keys. A `blocked` state must not be bypassed by removing DB uniqueness constraints or SSH restrictions. A lack of `LISTEN` alone does not authorize cancellation.

For an owner-authorized same-device/same-key stale-grant replacement, use `replace-stale --old-ticket OLD_TICKET --ticket NEW_TICKET --code NEW_CODE --host de2.nod.aqixnet.com --hostkey VERIFIED_PUBLIC_HOST_KEY --slot auto` first **without** `--apply`. Recheck the live target and obtain an explicit approval to revoke the named old grant, then run the identical command with `--apply`. Old and new device labels **and** keys must match; the old grant must be `approved`, the new ticket fresh and `pending`, and the old reverse port must not be listening. Replacement first revokes the old SSH authorization using the existing audited/backup mechanism and verifies the old listener closed, then approves the new ticket with TTL. No active tunnel is deliberately killed. If a connection appears during handover, stop: old may remain `revoking`, new remains pending. If the second phase fails, old stays revoked; inspect and retry the new approval separately. This two-stage operation is not a transparent atomic transaction, so do not report success before checking the new tunnel and operator SSH authentication.

**Deployment is separate and requires owner approval for the exact DE2 change.** Before deploying: compare live `/opt/hermes-enrollment/service.py` against the reviewed repository revision; back up that file, `requests.sqlite3` (online SQLite backup), and scoped `authorized_keys`; run a clean-sandbox test suite and dry-run preflight; verify `systemd` syntax and Python compilation. Plan rollback to the saved Python file and service restart, preserving/restoring DB/authorized keys only when necessary and reconciled against any enrollments since the backup. After approval, install only the reviewed service.py and its matching local session_guard.py dependency if different, restart only `hermes-enrollment.service`, verify both broker/SSH services, public registration health, read-only doctor, per-device key isolation, then a fresh owner-approved end-to-end Connector test. Do not touch active `23003` listener or legacy `JZUT9` without explicit permission.
